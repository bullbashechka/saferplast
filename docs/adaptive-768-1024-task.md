# Адаптация диапазона 768px-1024px

## Контекст

Задача по адаптации лендинга в диапазоне от `768px` до `1024px` временно отложена.
Нужно вернуться к ней отдельно, не затрагивая стандартную desktop-версию сайта.

## Общая цель

Сделать версию лендинга в диапазоне `768px-1024px` визуально близкой к desktop,
но без налезания блоков, переполнения текста и без перехода в полумобильное состояние.

Главный принцип:

- не ломать desktop-структуру;
- если блоки начинают не помещаться, уменьшать сами блоки, внутренние отступы и кегль;
- не переносить задачу на мобильную версию `<768px`;
- не ухудшать wide desktop `1400px+`.

## Правила для этого диапазона

- Все правки делать только для `768px-1024px`.
- Если поведение на `1024px` отличается от `1023px`, значит часть классов слишком рано переключается на `lg`.
- Для проблемных мест desktop-увеличения нужно сдвигать выше, если требуется, чтобы компактный режим сохранялся и на `1024px`.
- Если элемент лезет на соседний блок, сначала уменьшать его размеры и внутренности, а не менять глобальную сетку.

## Что уже всплыло

### HeroSection

- Два мини-блока под заголовком должны оставаться в одну линию.
- Эти два блока должны быть одинаковыми по размеру.
- Внутри них нельзя ломать текст и кнопки.
- Если блоки начинают лезть на фотографию справа, нужно уменьшать сами блоки внутри левой колонки.
- Стандартная desktop-версия hero не должна ломаться.

### Header

- В диапазоне `768px-1024px` пункты меню уходили на правую фотографию.
- Их нужно держать левее внутри левой части hero.
- Нельзя ухудшать стандартный desktop-header.

### WorkProcessSection

- В диапазоне `768px-1024px` текст внутри стеклянных плашек вылезал за границы.
- Для этого диапазона нужно уменьшать внутренние размеры карточек, а не менять общую структуру секции.

### ProjectsSection

- Сетка должна оставаться desktop-подобной.
- При уменьшении ширины экрана должны уменьшаться и сами блоки, и кегль внутри них.
- Верхняя и нижняя горизонтали колонок должны оставаться выровненными.

### LeadFormSection

- С `768px` не нужна трехколоночная декоративная сетка.
- В этом диапазоне должна оставаться только центральная форма.

## Подход к продолжению

При возвращении к задаче лучше идти по секциям по очереди:

1. `Header`
2. `HeroSection`
3. `WorkProcessSection`
4. `ProjectsSection`
5. остальные секции с переполнением или налезанием

После каждой правки проверять:

- `768px`
- `820px`
- `1024px`
- `1280px`
- `1400px`

## Проверка

После возобновления задачи обязательно прогонять:

- `npm.cmd run typecheck`
- `npm.cmd run lint`
